# 0.3.9 配置安全修复说明

本轮用户授权修复配置安全问题并重新生成免安装目录版。版本保持 0.3.9。原审计报告是历史反例，不再代表当前源码测试结果。

## 写入与恢复规则

- 编辑未启用供应商只保存资料；编辑当前供应商时，只有工具文件仍与 TokenPulse 上次写入一致才同步连接。外部修改后仅保存资料并提示「未覆盖」，需要重新接管时由用户明确启用。
- 当前供应商匹配同时考虑 URL、密钥、模型与接口，不能再凭同一网关地址认成另一个账号。URL 路径大小写保留。
- agent-config.ts 将供应商状态与工具文件纳入同步事务。写前核对读到的版本，单文件写临时文件/fsync/rename；操作保存私有 pending 日志，失败回滚仍属于本次写入的内容，外部改动优先。中断后在下次访问恢复未提交操作；已标记提交的操作只清理日志。写入互斥，日志恢复限制到明确的配置路径。
- agent-toml.ts 使用锁定版本 toml-eslint-parser 0.10.0 的 AST 范围修改值；修改前后解析校验，正确识别引号键、多行字面量、带点的表名和类型。未参与修改的 TOML 字节尽量保留，保留注释、CRLF 和用户扩展字段。Codex 使用独立 model_providers.tokenpulse_route，不删除用户的 custom 表。
- 开启路由保存本次接管前的配置快照，关闭/退出时优先恢复原始内容。若用户另加 hooks/MCP 等设置，则只反向恢复仍等于 TokenPulse 上次写入的字段，保留外部修改。桌面端保留原 profile 选择。外部已换走连接时不抢回控制权。
- 导入保留 Claude API_KEY/AUTH_TOKEN 及角色模型；Codex 保留布尔/数字类型，也兼容旧版已导入的字符串值和 CC 数据库中的 auth.OPENAI_API_KEY。
- 退出时若恢复失败，取消退出并说明原因，不悄悄留下指向已关闭代理的配置。成功恢复后关闭下游连接并中止对应上游请求、等待监听释放。

## 边界

- 旧版本已经接管、却没有接管快照的配置不能凭空恢复到准确原样。检测到这种情况会拒绝自动恢复并提示先备份、在原工具恢复直连；不猜测或覆盖用户配置。
- 对旧版本已丢失的角色配置或其他历史损坏，本轮不会在没有可靠原始数据时臆造修复。首次备份和原工具配置仍是恢复依据。
- 这是有明确回归覆盖的安全修复，不是完全移植 CC Switch，也不是文件系统层面对所有其他进程的原子比较交换。仍建议不要让两个管理器同时切同一工具。
- JSON 会重新序列化，但保留未管理字段；不承诺 JSON 文本字节格式完全不变。未运行真实供应商远端 API/CLI 端到端测试，不把这些自动化断言当成上游兼容性保证。
